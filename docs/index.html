RL environment · agent evaluation · Indian tax

Can an AI agent file India's GST return without cheating its way to the answer?

An RL environment where an agent reads a month of invoices through tools and files GSTR-3B, India's monthly GST return. A deterministic solver computes the right answer, the reward grades the outcome rather than the steps, and an audit of 10 cheating and shortcut strategies checks the reward can't be gamed.

The gap

Agents train on Western SaaS, not on compliance

Most agent environments target Salesforce, Jira or a spreadsheet. Compliance work in emerging markets has almost none, though it is rule-heavy, checkable and expensive to get wrong. India has over 1.4 crore GST registrations filing returns every month.

GSTR-3B is a good first task because the right answer is exact. Tax splits by state, some purchases can't be claimed, some tax must be paid in cash, and credit has to be used in a statutory order. A model that skims gets it wrong, and a grader can prove it.

Tasks are generated from a seed, so every run is reproducible and the answer key never ships with the task.

The solver

Rule 88A, solved exactly

The hardest part of the answer is how credit pays tax. IGST credit must be used first, and CGST and SGST credit can never cross: ₹5,000 of CGST credit can't pay ₹1,000 of SGST. Within those rules, the filer chooses how to split IGST credit between CGST and SGST, and a bad split costs real cash.

The solver checks every breakpoint of that split and keeps the one with the least cash outflow. Reverse-charge tax is always paid in cash, however much credit is available.

The test suite checks the solver against brute-force search over every possible split on 300 random cases.
Outcome-based grading

Grade the return, not the route

13 fields

Taxable value, nil-rated value, outward tax, reverse-charge tax and eligible credit per head, blocked credit, and cash payable.

The total counts most

Cash payable carries weight 5; the per-head fields catch a right total reached for the wrong reasons.

Zeros can't earn

A field whose true value is zero can only lose reward. An empty or all-zero return scores 0.

Any interface

Only the submitted return is graded, so the same tasks work for tool-use, GUI and plain-text agents.

The first version failed this audit three ways: all zeros scored 0.46 on easy tasks, pooling credit across heads passed every task, and paying reverse-charge tax from credit passed 96%. The zero-field penalty, an uneven credit ledger on hard tasks and a per-task inter-state mix fixed them.

Credit pooling still passes 57% of hard tasks. On those tasks the head-wise rule genuinely doesn't change the answer, so the pass is earned. A planned expert tier targets it directly.

A regression test fails the build if any no-work strategy earns reward or any shortcut passes more than 65% of hard tasks.

What this doesn't cover

Scope and simplifications

This version tests GST computation. Since July 2025, GSTR-3B's outward liability auto-fills from GSTR-1 and is locked, and credit flows from GSTR-2B through the Invoice Management System. Modelling that GSTR-1 → IMS → 2B → 3B workflow is the next tier.

Rates

Post-September 2025 slabs (0/5/18/40). No cess.

Credit

Blocked credit is all-or-nothing per invoice; no Rule 37/42/43 reversals or 2B mismatches.

Documents

No credit or debit notes, amendments, advances, interest or late fees.

Review

The simplifications are pending review by a chartered accountant.
